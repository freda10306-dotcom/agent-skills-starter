# 0001 轉錄在本機做，只送遮蔽後的文字到外部 LLM

Status: Proposed

## 決定

- 原始影音的轉錄在本機或組內的機器上跑，不用外部語音轉錄 API。
- 摘要、話題分類、漏問檢核可以用外部 LLM，但只送遮蔽後的逐字稿（見 0003）。
- 原始資料（原始影音、未遮蔽逐字稿）永遠不送出本機或專案自己的 Supabase。

## 否決的選項

- **全部本機／自架**：最安全，但中文摘要品質和硬體需求在兩個月內都沒把握。
- **全部外部 API，靠服務條款＋同意書**：brief 限制 5 明說個資不能外流到第三方 AI，條款擋不住這條。
- **依資料來源分流**：要維護兩條處理路徑，而且一旦分錯流就是外流。

## 為什麼

原始影音最敏感也最難遮蔽，所以留在本機。文字可以先遮蔽再送出，保住外部 LLM 的摘要品質。代價有兩個：

- 遮蔽召回率成了安全關鍵指標，漏遮一筆就是外流。
- 要自己處理本機轉錄的速度和硬體問題，跑在哪台機器還沒定，見 decision-log。
